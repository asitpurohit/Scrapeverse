# Why ScrapeVerse Uses Store-Specific Collectors

## Decision

ScrapeVerse does not use one universal product collector for every Shopify store.

Instead, it creates one Bright Data Scraper Studio collector for each normalized
`domain + platform` pair. The collector is created once during the first product
visit, verified, saved in the `stores.collector_id` field, and reused for later
product pages from that store.

## Why a Universal Collector Was Rejected

Shopify is a common commerce platform, but Shopify stores do not have one common
product-page layout. Store owners choose different themes, apps, templates,
HTML structures, naming conventions, and product data presentations.

The same universal collector was tested against four stores:

| Store | Result from the same collector |
|---|---:|
| Japam | 9/9 required fields |
| Phool | 3/9 required fields |
| Suta | 6/9 required fields |
| Heads Up For Tails | 4/9 required fields |

### Japam

The collector was created from a Japam product page and returned the complete
product record:

```json
{
  "product_id": "9637492424986",
  "product_title": "Pyrite Wealth Band",
  "active_price": 699,
  "compare_at_price": 1299,
  "currency": "INR",
  "brand": "Japam",
  "image_url": "...",
  "description": "...",
  "category": "Bracelets"
}
```

### Phool

The same collector returned only:

```json
{
  "product_id": "8882595987646",
  "currency": "INR",
  "brand": "PHOOL"
}
```

The title, prices, image, description, and category were missing.

### Suta

The same collector returned the product ID, title, currency, brand, description,
and category, but missed the active price, compare-at price, and image.

### Heads Up For Tails

The same collector returned the product ID, currency, brand, and description, but
missed the title, prices, image, and category.

These results show that a collector generated from one store's page structure
cannot reliably extract fields from another store's page structure.

## Shopify Data Is Not Uniform Enough

Shopify's product JSON commonly exposes fields such as `product_type` and `tags`,
but the values are controlled by each store and may be empty.

For example:

- Japam provided `product_type: "bracelet"`.
- Phool provided an empty `product_type` and empty `tags`.
- Neither store exposed a universal `subcategory` field.

Therefore, category extraction must be adapted to the store's actual page and
embedded data. The collector can use the store's product type, collection,
breadcrumb, or page category when available. `ai_category` is generated by the
application separately and is used as a weighted similarity signal.

## Why the Key Includes Platform

The store key is:

```text
normalized domain + platform
```

This prevents a Shopify collector from being incorrectly reused for a
WooCommerce, Magento, or custom store on the same domain. Different platforms
can expose different APIs, page structures, pricing formats, and product
identifiers.

## Store Collector Lifecycle

```text
First product visit
        ↓
Find store by domain + platform
        ↓
Collector exists and is ready?
        ├─ Yes → run the stored collector
        └─ No  → create collector asynchronously
                         ↓
                  verify its first result
                         ↓
                  save collector_id in stores
                         ↓
                  run product scrape
```

While the collector is being created:

- The backend returns `202 collector_provisioning`.
- No incomplete product data is returned.
- The extension shows no product top bar.
- The extension quietly polls until the collector is ready.
- Creation retries with backoff when Bright Data reports an error.

After creation, later visitors reuse the saved collector. The application does
not call `scraper create` again for every product or every customer.

## Required Product Output

Each store-specific product collector is instructed to return:

```json
{
  "product_id": "...",
  "product_title": "...",
  "active_price": 0,
  "compare_at_price": 0,
  "currency": "INR",
  "brand": "...",
  "image_url": "...",
  "description": "...",
  "category": "..."
}
```

The collector does not scrape `stock`, `tags`, `subcategory`, reviews, or
ratings. Review scraping is a separate workflow.

## Trade-Off

Store-specific collectors require one-time provisioning and create more
collector records in Bright Data. In return, they provide:

- Extraction logic matched to the real store page.
- Better field completeness.
- Correct store-specific price and image selectors.
- Isolation when one store changes its theme.
- Safer self-healing because a repair affects only that store's collector.

This is the correct trade-off for reliable product data. A universal collector
is simpler to configure, but the tests showed that it produces incomplete and
unsafe product records across different stores.
